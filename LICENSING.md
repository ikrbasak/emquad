# Licensing and attribution

emquad is **MIT** licensed ([LICENSE](LICENSE)). What follows is the obligation
that comes with shipping other people's code inside our binary, and how it is
enforced rather than remembered.

## Why this needs care

`@emquad/core` ships a **prebuilt native binary that statically links ~290 Rust
crates**, Typst among them. Static linking means every one of those licenses
travels with the `.node` file that users install. Nothing about that is onerous
— the whole tree is permissive, with no copyleft — but attribution is not
optional, and a license audit at release time is far too late.

Two obligations in particular:

- **Typst is Apache-2.0, not MIT.** Our own license does not change that. The
  Apache-2.0 attribution and license text must ship.
- **The default fonts are not OFL, or not only OFL.** They span four separate
  licenses, one of which is GPL-3.0-or-later with exceptions. Getting this wrong
  is the single largest compliance risk in the project. See below.

## How it is enforced

| Check | Command | Runs |
|---|---|---|
| License allow-list | `cargo deny check licenses` | pre-push, CI, release |
| Attribution file | `pnpm notices` | CI verifies it is current |
| No `-sys` crates | `./scripts/check-no-sys-crates.sh` | pre-commit, CI |

Install the tools once:

```sh
cargo install cargo-deny --locked
cargo install cargo-about --locked --features cli
```

[`deny.toml`](deny.toml) holds an **exhaustive** allow-list, not a permissive
one. A dependency introducing an unlisted license fails the build. That is
deliberate: a build failure is the only moment anyone actually reads a license.
As of the current tree the list is `0BSD`, `Apache-2.0`,
`Apache-2.0 WITH LLVM-exception`, `BSD-2-Clause`, `BSD-3-Clause`, `BSL-1.0`,
`CC0-1.0`, `MIT`, `Unicode-3.0`, `Unlicense`, and `Zlib`.

[`THIRD-PARTY-NOTICES.md`](THIRD-PARTY-NOTICES.md) is generated by `cargo about`
from [`about.hbs`](about.hbs) and **committed**, so attribution changes appear in
a diff rather than only inside a CI log. Do not edit it by hand. It attributes
shipping dependencies only — `ignore-dev-dependencies` is on, because
attributing test-only crates would overstate what is distributed.

## `@emquad/fonts` — read this before touching that package

`cargo deny` cannot help here: the fonts are data inside an npm package, not
crates. And the common shorthand — "the default fonts are OFL" — is **wrong**.
The 17 files that `typst_assets::fonts()` yields carry **four different
licenses**, verified against the `NOTICE` file shipped in `typst-assets` 0.15.1:

| Files | License |
|---|---|
| `LibertinusSerif-*.otf` (6) | SIL Open Font License 1.1 |
| `NewCMMath-*.otf` (3), `NewCM10-{Bold,Italic,BoldItalic}.otf` (3) | GUST Font License 1.0 (LPPL 1.3c or later) |
| `NewCM10-Regular.otf` (1) | **GPL-3.0-or-later** with Font and Distribution Exceptions |
| `DejaVuSansMono*.ttf` (4) | Bitstream Vera / DejaVu (Arev glyphs © Tavmjong Bah) |

### The one that could actually bite

`NewCM10-Regular.otf` is GPL-3.0-or-later. Two exceptions make it shippable:

- The **Font Exception** means a PDF that embeds the font is not thereby GPL.
  That covers our users' documents.
- The **Distribution Exception** means shipping the font inside a program under
  a GPL-3-compatible license does not make that program GPL. MIT is
  GPL-3-compatible, so `@emquad/fonts` is fine — **as long as the file is
  distributed unmodified.**

The exception text is explicit about the condition:

> If however you distribute a copy of the fonts that modifies either the glyphs
> (one or more) or the glyph-set by adding or removing glyphs, this exception is
> invalidated and your program has to follow GPL version 3 (or later).

So: **never subset, re-encode, or otherwise rewrite the shipped font files.**
That is a live risk rather than a theoretical one — 9.3 MB is the largest single
item in the install footprint and subsetting is the obvious way to shrink it.
Doing so to `NewCM10-Regular.otf` would relicense `@emquad/fonts` as GPL-3.
Ship the bytes verbatim; if the size must come down, drop whole families
instead.

### Requirements on that package

1. Ship every license text above, verbatim, in the tarball under `licenses/`.
   Reproducing `typst-assets`' own `NOTICE` file is the simplest way to be sure
   nothing is missed.
2. Declare the SPDX expression honestly in `package.json`:
   `"license": "OFL-1.1 AND LPPL-1.3c AND GPL-3.0-or-later AND Bitstream-Vera"`.
   It is **not** MIT like the rest of the workspace.
3. Preserve reserved font names. OFL-1.1 restricts renaming, so the files ship
   under their original names.
4. Add a packaging test asserting each shipped font file is byte-identical to
   its `typst-assets` original. That turns the constraint above into something
   CI enforces rather than something a reviewer has to remember.

Fonts are a separate optional package precisely so all of this stays visible
instead of being buried inside a 29 MB binary — and so users who bring their own
fonts never take on any of it.

## Adding a dependency

1. Run `cargo deny check licenses`. If it fails, read the license before
   touching the allow-list.
2. Run `pnpm notices` and commit the regenerated `THIRD-PARTY-NOTICES.md`.
3. Confirm `./scripts/check-no-sys-crates.sh` still passes — a `-sys` crate
   usually means a C toolchain, which breaks the cross-compile matrix
   (hard rule 4). Exactly two are allowed, both bindings-only with no C build
   step: `windows-sys`, and `napi-sys`, which resolves N-API symbols against the
   host Node binary at load time.
