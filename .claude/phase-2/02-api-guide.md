# API guide — `@emquad/typst-binding`

**This is not the public API.** It is the internal napi surface that `@emquad/core` wraps in
Phase 3. Everything here is generated into
[`packages/binding/index.d.ts`](../../packages/binding/index.d.ts) with the doc comments intact,
so that file is the reference; this document explains the shapes and the reasons.

Every example is drawn from a passing test in
[`packages/binding/test/binding.test.js`](../../packages/binding/test/binding.test.js).

## Getting a build

```sh
pnpm --filter @emquad/typst-binding run build        # release
pnpm --filter @emquad/typst-binding run build:debug  # debug, fast to rebuild
pnpm --filter @emquad/typst-binding run build:test   # debug + the `test-hooks` feature
pnpm --filter @emquad/typst-binding test             # build:test, then the Node suite
```

`index.js` and `index.d.ts` are generated by napi-rs. Do not edit them; they are also excluded
from oxlint and oxfmt for that reason.

## Constructing a compiler

```js
import { Compiler } from '@emquad/typst-binding';

const compiler = new Compiler({
  fonts: [readFileSync('Inter.ttf')],          // required, at least one that parses
  files: { '/templates/invoice.typ': '#let invoice(n) = [Invoice #n]' },
  packages: [{ spec: '@preview/cetz:0.4.2', path: 'lib.typ', data: bytes }],
  poolSize: 8,               // default: availableParallelism()
  queueCapacity: 1024,       // default: 1024
  cacheMaxAge: 16,           // default: 16; `false` disables eviction
  pinRayon: false,           // default: false — see below
});
```

Expensive to construct, cheap to share. Everything in the constructor — parsing fonts, building
the `FontBook`, building the base VFS — happens once. Rebuilding it per request would invalidate
the memo cache and destroy throughput.

**`fonts` is required and must contain at least one parsable face.** With none, typst compiles
*successfully* and emits a valid PDF with every text run silently dropped and zero diagnostics.
The constructor throws `NO_FONTS` instead.

**`pinRayon` defaults to `false`.** Phase 2 measured it: no benefit at any pool size, ~15% cost
at low concurrency. See [`03-findings.md`](03-findings.md#1-hard-rule-9-is-retracted-rayon-pinning-does-not-help-).

**`cacheMaxAge` is process-global in effect.** Two `Compiler` instances share one `comemo`
cache; this setting belongs to whichever pool runs the compile, not to a document.

## Compiling

```js
const result = await compiler.compile({
  source: '= Invoice\n#lorem(20)',    // written to /main.typ
  files: { '/data.json': jsonBuffer },
  clock: { fixed: 1_785_888_000 },
  pdf: { tagged: true, ident: 'invoice-v1' },
});

const sync = compiler.compileSync({ source: '= Invoice' });
```

`compileSync()` is not a hedge. For batch workloads — N processes each looping over documents —
async scheduling is pure overhead and sync is faster. It is also the right call inside an
existing `worker_thread`, where the pool would only add a hop.

### The rule that matters most

**Vary content, never paths.**

```js
// Correct. One interned path, forever.
await compiler.compile({ source: renderInvoice(order) });

// Wrong. Leaks an interned path per request; the process dies at ~65k renders.
await compiler.compile({
  files: { [`/invoice-${order.uuid}.typ`]: body },
  main: `/invoice-${order.uuid}.typ`,
});
```

VFS paths are interned process-wide and never freed. The guard trips at 50,000 and names the
offending pattern, but the guard is a safety net — the discipline is the fix.

### Files accept `string | Buffer | Uint8Array`

Strings are UTF-8 encoded; binary data is stored as-is, which is what makes images work.
`Buffer` needs no special handling — it *is* a `Uint8Array`.

### Mounting a `@preview` package

Mount `typst.toml` as well. Typst reads it to find the entrypoint, and the import fails with a
file-not-found error naming a file the caller never asked for.

```js
packages: [
  { spec: '@preview/example:0.1.0', path: 'typst.toml', data: manifest },
  { spec: '@preview/example:0.1.0', path: 'lib.typ', data: source },
]
```

## The result shape

```ts
{ ok: true,  pdf: Buffer, warnings: Diagnostic[], pages: number }
{ ok: false, pdf: null,   warnings: [],           error: CompileFailure }
```

**A failed compile is returned, not thrown.** A promise rejection can only carry a
`napi::Error` — a message and a status — so diagnostics, positions, and hints would have to be
flattened into a string, and the sync and async paths would disagree about shape. Phase 3 turns
the failure branch into a thrown `Error` subclass, which is where a JS subclass belongs anyway.

**Argument and usage errors do throw**, because they are programming mistakes rather than
outcomes: an unknown PDF standard, a full queue, an empty font set.

```js
const result = await compiler.compile({ source: 'ok\n#undefined_function()' });
if (!result.ok) {
  console.error(result.error.code);                    // 'COMPILE_FAILED'
  console.error(result.error.diagnostics[0].position); // { file: '/main.typ', line: 2, column: 2 }
}
```

### Error codes

Branch on `code`, never on `message`.

| Code | Meaning |
|---|---|
| `COMPILE_FAILED` | Typst reported fatal errors |
| `EXPORT_FAILED` | Compiled, but PDF export failed — usually standards conformance |
| `NO_FONTS` | No fonts registered (thrown, at construction) |
| `PATH_VOCABULARY_EXHAUSTED` | The interner guard tripped |
| `INVALID_PATH` | Not a valid virtual path — e.g. it escapes the root |
| `INVALID_PACKAGE_SPEC` | Unparsable package specification |
| `MAIN_NOT_FOUND` | The main file is in neither VFS layer |
| `INVALID_PDF_SETTINGS` | Mutually incompatible export options |
| `PANIC` | A Rust panic was caught — always a bug, never fatal to the process |
| `QUEUE_FULL` | Thrown. The pool's bounded queue is full |

### Read the warnings on success

They are the most likely place a silently-wrong document announces itself.

```js
const { warnings } = await compiler.compile({ source });
for (const w of warnings) {
  console.warn(`${w.severity} at ${w.position?.file}:${w.position?.line}: ${w.message}`);
  for (const hint of w.hints) console.warn(`  hint: ${hint.message}`);
}
```

Line and column are **1-based**, and columns count characters rather than bytes. A hint can
carry its own position, pointing at different code than the diagnostic it belongs to.

## PDF options

```js
pdf: {
  tagged: true,                       // default; accessibility
  pretty: false,
  standards: ['a-2b'],                // '1.4'..'2.0', 'a-1b'..'a-4e', 'ua-1'
  pageRanges: [{ start: 2, end: 4 }], // requires tagged: false
  ident: 'invoice-template-v1',       // must be stable, or omitted
  creator: 'my-service',              // or false to omit the field
  timestamp: false,                   // or unix seconds
}
```

**`tagged` defaults to `true` and should stay that way.** Phase 0 measured +5–28% compile time
but **up to +302% output size**. The cost is size, not time; turning it off is an accessibility
regression users will not notice, so make it their explicit choice.

**Page ranges require `tagged: false`.** An accessibility structure tree describes the whole
document and cannot describe a subset. Typst catches this at export, after a full compile has
been paid for; this layer catches it before one starts.

## Reproducible output

Three things vary between runs: the clock, `ident`, and the timestamp. Pin all three.

```js
const request = {
  source,
  clock: { fixed: 1_785_888_000 },
  pdf: { ident: 'statement-v1', timestamp: false },
};
// Byte-identical, run to run, and identical between compile() and compileSync().
```

## The clock

```js
clock: { fixed: 1_785_888_000 }        // a fixed instant, UTC
clock: { offsetMinutes: 330 }          // system time at UTC+05:30
clock: { unavailable: true }           // datetime.today() errors in the document
```

**Watch the sign.** `offsetMinutes` is east of UTC; `Date.prototype.getTimezoneOffset()` returns
the opposite, so negate it at the boundary.

## Backpressure

`compile()` **throws** `QUEUE_FULL` when the bounded queue is full. It does not block — that
would block the event loop — and it does not grow, which would turn sustained overload into an
out-of-memory crash.

```js
try {
  await compiler.compile(request);
} catch (error) {
  if (error.message.includes('QUEUE_FULL')) {
    // shed load, retry with backoff, or raise queueCapacity
  }
}
```

## Metrics

```js
compiler.stats;
// { poolSize, queueCapacity, queued,
//   internedPaths, trackedPaths, pathLimit, pathCap }
```

Export **`internedPaths / pathLimit`**. It is the number that predicts a crash: paths are never
freed, and typst panics at `pathCap` (65,535). `queued` is the backpressure signal.

```js
compiler.fontFamilies;   // sorted, deduplicated — why `text(font: "…")` did not match
```

## Module functions

```js
typstVersion();       // '0.15.1' — pre-1.0, so rendering changes across minor releases
evictCache(16);       // for compileSync callers; the pool does this itself
setPathLimit(50_000); // lower the guard; raising it past 65,535 is refused
```
