# Tooling

Formatting, linting, git hooks, and license compliance. All of it also runs in CI when Phase 4
builds CI — the hooks exist to make feedback immediate, not to be the only place a check
happens.

## One-time setup

```sh
pnpm install                  # JS dev tools; `prepare` runs `lefthook install`
cargo install cargo-deny --locked
cargo install cargo-about --locked --features cli    # the `cli` feature is required
```

`pnpm install` installs the git hooks. If it was run with `--ignore-scripts`, install them
explicitly:

```sh
pnpm exec lefthook install
```

## Everyday commands

| Command | What it does |
|---|---|
| `pnpm fmt` | `oxfmt` on JS/TS/JSON, `cargo fmt` on Rust |
| `pnpm fmt:check` | Same, non-mutating |
| `pnpm lint` | `oxlint --deny-warnings` and `cargo clippy -- -D warnings` |
| `pnpm test` | `cargo test` |
| `pnpm bench` | `cargo bench` |
| `pnpm licenses` | `cargo deny check licenses` and regenerates `THIRD-PARTY-NOTICES.md` |

## Rust

**`rustfmt.toml`** — `max_width = 96`, `use_small_heuristics = "Max"`. The wide small-heuristics
setting keeps short structs and matches on one line, which suits this codebase's many small
mapping functions.

**`rust-toolchain.toml`** pins 1.97.1 so formatting is byte-stable across machines. Edition
2024.

**Lints** live in the workspace `Cargo.toml` and are inherited via `[lints] workspace = true`:

```toml
[workspace.lints.rust]
unsafe_code = "forbid"              # a napi binding is where a stray unsafe is hardest to review
unused_qualifications = "warn"
missing_debug_implementations = "warn"

[workspace.lints.clippy]
all = { level = "warn", priority = -1 }
dbg_macro = "warn"
todo = "warn"
```

`unsafe_code = "forbid"` is not aspirational — nothing in the workspace needs it, and Phase 2
should keep it that way, confining any unavoidable `unsafe` to napi-generated code rather than
hand-written blocks.

The release profile carries a comment worth preserving: **never `panic = "abort"`.** It
disables `catch_unwind`, which hard rule 2 depends on, and typst's `FileId` interner panics via
`expect`.

## JavaScript and TypeScript

**oxlint** (`.oxlintrc.json`) — `correctness` and `suspicious` as errors, `perf` and `pedantic`
as warnings, plus `no-console`, `eqeqeq`, `consistent-type-imports`, `no-explicit-any`,
`prefer-node-protocol`, and `no-default-export`. Config files are exempt from the last one.

**oxfmt** (`.oxfmtrc.json`) — defaults, with markdown and YAML excluded. That exclusion is
deliberate: the documents under `.claude/` are hand-wrapped prose with hand-aligned tables, and
reformatting them would produce churn that buries real changes. `spike/`, `target/`, `dist/`,
and the generated `THIRD-PARTY-NOTICES.md` are excluded too.

**commitlint** (`commitlint.config.js`) — Conventional Commits with a **closed scope list**:
`engine`, `napi`, `core`, `fonts`, `resolver`, `ci`, `deps`, `docs`, `repo`. A closed list means
a typo fails the commit instead of quietly inventing a scope. Add to the list when a new package
appears.

## Git hooks

`lefthook.yml`. Validate changes with `pnpm exec lefthook validate`.

**pre-commit** (parallel, scoped by glob so unrelated commits are not slowed):

| Job | Runs on |
|---|---|
| `rustfmt` | `*.rs` |
| `clippy` | `*.rs`, `*.toml` |
| `oxfmt` | JS/TS/JSON |
| `oxlint` | JS/TS |
| `no-sys-crates` | `*.toml`, `*.lock` |

**pre-push:** `cargo test --all-features`, and `cargo deny check licenses` when manifests
changed.

**commit-msg:** commitlint.

### `scripts/check-no-sys-crates.sh`

Guards hard rule 4. Zero `-sys` crates means no OpenSSL, no bindgen, no cmake, and no C
toolchain beyond what `psm`/`stacker` already need — which is the single property that makes a
14-target build matrix affordable, and the reason networking lives in TypeScript.

That property is lost one careless dependency at a time, so it is checked at the commit that
adds one rather than discovered in Phase 4. `windows-sys` is allowed: bindings only, no C build
step.

## License compliance

Full policy in [`../../LICENSING.md`](../../LICENSING.md). In brief:

- **`deny.toml`** holds an **exhaustive** license allow-list, not a permissive one. A dependency
  introducing an unlisted license fails the build, which is the only moment anyone actually
  reads a license. Verified clean across all 293 packages — every one permissive, none copyleft.
- **`THIRD-PARTY-NOTICES.md`** is generated by `cargo about` from `about.hbs` and **committed**,
  so attribution changes appear in a diff rather than only in a CI log. 5,000 lines covering
  290 crates. Do not edit it by hand.
- **`@emquad/fonts` is manual and is the risky one.** `cargo deny` cannot see fonts — they are
  data in an npm package, not crates. The default fonts span four licenses including
  GPL-3.0-or-later, and subsetting them to save space would relicense that package as GPL-3.
  See hard rule 11.

Regenerate notices after any dependency change:

```sh
pnpm licenses
```

## Benchmarks

```sh
cargo bench --bench compile               # invoice, 2000 documents
EMQUAD_DOC=multirun cargo bench --bench compile
EMQUAD_DOCS=10000 cargo bench --bench compile
EMQUAD_PIN=0 cargo bench --bench compile  # leave typst's rayon alone

cargo bench --bench soak                          # 20k compiles, evict(16)
EMQUAD_SOAK=100000 EMQUAD_EVICT=none cargo bench --bench soak

./scripts/benchcmp.sh multirun            # pinned vs unpinned, separate processes
```

No criterion, deliberately. The interesting quantity is steady-state throughput over *distinct*
documents, and criterion's repeat-until-stable sampling works against that — repeating one
document measures the memo cache rather than the compiler.

**Two traps these benchmarks encode. Do not rediscover them.**

1. **A probe that never calls `typst::compile` measures nothing.** With `lto = true` the linker
   dead-strips the whole pipeline; a Phase 0 probe once reported 376 KB for a full typesetting
   engine. Every bench consumes its output through `black_box`.
2. **Comparing configurations in one process is unreliable**, even with disjoint document
   indices — disjoint indices are not disjoint work. Use `benchcmp.sh`, which runs one
   configuration per process with repeated, alternating order. See
   [`03-findings.md`](03-findings.md#2-disjoint-document-ranges-are-not-enough-).
